AgentBazaar

Team1 Codebase Hackathon : Chula Edition အတွက် ၄ နာရီခွဲ အတွင်း ဆောက်ရန် လမ်းညွှန်
Track: AI Agent။ Chain: Avalanche Fuji (chain ID 43113)။ တစ်ယောက်တည်း ဆောက်မည်။

၁။ အကဲဖြတ်ချက် အကျဉ်း

Idea က ကောင်းသည်။ AI Agent track ၏ ဖော်ပြချက်ဖြစ်သော "micropayment rails via agent-to-agent transactions" နှင့် တိုက်ရိုက် ကိုက်ညီသည်။ Judge တွေ မြင်ရမည့် ဇာတ်လမ်းက ရှင်းသည်။ Agent တစ်ကောင်ကို ပိုက်ဆံ ၅၀ ဆင့် ပေးလိုက်သည်၊ သူက တခြား agent တွေကို ငှားသည်၊ ပိုက်ဆံ ပေးသည်၊ ညံ့တဲ့ agent ကို အမှတ်နည်းနည်း ပေးပြီး နောက်တစ်ခါ မငှားတော့ပါ။ အားလုံး Avalanche ပေါ်မှာ မြင်ရသည်။

အဓိက ပြဿနာ: Folder ထဲက PRD က ၂၄ နာရီမှ ၄၈ နာရီ အတွက် ရေးထားသည်။ Hackathon က ၄ နာရီခွဲသာ ရှိသည် (၁၀:၅၀ မှ ၁၅:၃၀)။ PRD အတိုင်း အကုန် ဆောက်လျှင် ဘာမှ မပြီးဘဲ ဆုံးမည်။ ထို့ကြောင့် အောက်ပါ "၄ နာရီ version" အတိုင်းသာ ဆောက်ရမည်။

၆။ Demo Script (၃ မိနစ်)

  1. Hook (၁၅ စက္ကန့်): "ကျွန်တော့် AI agent ကို ၅၀ ဆင့် ပေးလိုက်ပြီး မေးခွန်း တစ်ခု မေးလိုက်ပါတယ်။ သူက တခြား AI တွေကို ငှားမယ်၊ ပိုက်ဆံ ပေးမယ်၊ ညံ့တဲ့ကောင်ကို ထုတ်ပစ်မယ်။ အားလုံး Avalanche ပေါ်မှာ။"
  2. Registry (၂၀ စက္ကန့်): Snowtrace ပေါ်က verified contract နှင့် agent leaderboard ပြပါ။
  3. မေးခွန်း (၂၀ စက္ကန့်): "Should I build a game on Avalanche right now?" ကို 0.05 AVAX budget ဖြင့် မေးပါ။ Plan နှင့် ခန့်မှန်း ကုန်ကျစရိတ် ပြပြီး approve နှိပ်ပါ။
  4. Live economy (၆၀ စက္ကန့်): Feed ထဲတွင် agent ရွေးရသည့် အကြောင်းပြချက်၊ USDC payment နှင့် Snowtrace link၊ rating tx၊ budget meter ကျသွားသည်ကို ပြပါ။
  5. Reputation moment (၃၀ စက္ကန့်): Budget Analyst က ညံ့သော အဖြေ ပြန်သည်။ ၁/၅ rating ကို on-chain တင်သည်။ ဒုတိယ မေးခွန်း မေးလျှင် သူ့ကို ကျော်သွားသည်။ ဒါက wow moment ဖြစ်သည်။
  6. Report (၂၀ စက္ကန့်): နောက်ဆုံး အဖြေ၊ စုစုပေါင်း ကုန်ကျစရိတ်၊ receipt များ။
  7. နိဂုံး (၁၅ စက္ကန့်): "No accounts, no API keys, no middleman. An open agent economy with public reputation on Avalanche."

AI က budget ကျော်ပြီး သုံးနိုင်လား။မရပါ။ Budget စစ်ဆေးမှုက code ထဲမှာ ဖြစ်သည်၊ LLM output ကို မယုံပါ။ Payment တိုင်း မတိုင်မီ remaining budget ကို စစ်သည်။ Session တစ်ခုလျှင် paid call အများဆုံး ၁၀ ခု။
ဘယ်သူမဆို rateJob ခေါ်လို့ ရတာ ပြဿနာ မရှိလား။သိပါသည်။ PaymentRef တစ်ခုလျှင် တစ်ကြိမ်သာ rate လုပ်နိုင်သည်။ နောက်တစ်ဆင့်တွင် paymentRef ကို USDC transfer နှင့် on-chain verify လုပ်မည်။ ERC-8004 ပုံစံကို လိုက်နာထားသည်။
x402 ဆိုတာ ဘာလဲ။HTTP 402 status ကို သုံးပြီး API call တစ်ခုချင်းစီကို stablecoin ဖြင့် ပေးချေသည့် standard ဖြစ်သည်။ Account, API key မလိုပါ။ (Plan B သုံးထားလျှင် "x402 pattern ကို ရိုးရှင်းစွာ ကိုယ်တိုင် implement လုပ်ထားသည်၊ USDC transfer tx hash က payment proof ဖြစ်သည်" ဟု ရိုးသားစွာ ပြောပါ။)
ဘာကြောင့် Avalanche လဲ။Sub-second finality ကြောင့် agent က ပေးချေပြီး ချက်ချင်း အလုပ် ဆက်လုပ်နိုင်သည်။ Gas သက်သာသဖြင့် $0.01 payment ဖြစ်နိုင်သည်။

၇။ အန္တရာယ်များနှင့် ဖြေရှင်းနည်း

Faucet မရခြင်းယနေ့ ယူထားပါ။ Organizer ထံ faucet code တောင်းပါ။ USDC မရလျှင် ကိုယ်ပိုင် mock USDC (ERC20) deploy လုပ်ပြီး သုံးပါ၊ judge ကို ပြောပါ။

၈။ App ကို ဆောက်ပြီးပါပြီ။ Event နေ့ command များ

Code အားလုံးက hackathon/agentbazaar/app ထဲမှာ ရှိပါပြီ။ Fuji ကို fork လုပ်ထားသော local chain ပေါ်တွင် x402 payment, on-chain rating, bad agent ကို ရှောင်ခြင်း အထိ စမ်းသပ် အောင်မြင်ပြီး ဖြစ်သည်။ Event နေ့တွင် အောက်ပါ အဆင့်များသာ လုပ်ရမည်။

#လုပ်ရန်Command / အသေးစိတ်
၁.env ဖြည့်ရန်cp .env.example .env ပြီး PRIVATE_KEY (orchestrator wallet), PROVIDER_ADDRESS, ANTHROPIC_API_KEY, SNOWTRACE_API_KEY ထည့်ပါ။
၂Contract deploy + verifyset -a; source .env; set +a ပြီး npm run deploy။ ထွက်လာသော address ကို .env ထဲ REGISTRY_ADDRESS အဖြစ် ထည့်ပါ။
၃Agent ၃ ကောင် registernpm run seed (transaction ၃ ခု)
၄Runnpm run dev ပြီး browser တွင် http://localhost:3000 ဖွင့်ပါ။ တခြား terminal တွင် npm run check နှင့် npm run smoke ဖြင့် စစ်ပါ။

ပြဿနာ ရှိလျှင်

  • Payment: Default က PAY_MODE=avax ဖြစ်ပြီး AVAX ကို တိုက်ရိုက် ပို့ကာ tx hash ကို proof အဖြစ် သုံးသည်။ x402 USDC ကို ပြချင်လျှင် PAY_MODE=x402 ပြောင်းပြီး USDC ယူရန် လိုသည်။
  • Anthropic API မရလျှင်: MOCK_LLM=1 ထည့်ပါ။ Payment နှင့် rating က အစစ်၊ အဖြေ စာသားသာ mock ဖြစ်မည်။
  • Internet မရလျှင်: README ထဲ "No internet" အပိုင်းအတိုင်း anvil fork ဖြင့် run ပါ။
